YOLO-World · 开放词汇检测（路线 A）

目标把固定 80 类（COCO）的 YOLO-Lite 检测器，升级为用任意文本提示词就能检测的开放词汇检测器，无需重新训练。

思路用 YOLO-World 的 YOLOv8 同族架构替换分类头：检测框由网络回归，类别由 视觉嵌入 · 文本嵌入 的相似度决定。文本嵌入来自 CLIP 文本塔（本 Demo 用 yoloworld_text_tower.py 提供）。

1. 为什么选 YOLO-World（路线 A）

对比三条扩展路线：

路线做法优点缺点
A 开放词汇YOLO-World + CLIP 文本塔任意类别、免重训、复用 YOLOv8 解码器需 CLIP 文本塔服务
B 微调自有数据微调 80 类精度高、可离线仍为固定类别
C 实例分割YOLOv8-seg 扩展 C++ 解码得到掩码需改解码+掩码绘制

路线 A 与本家族（v8/v11/v26）的 ncnn 输出同构，解码器可直接复用，是“扩大识别目标”性价比最高的方案。

2. 端到端流程

摄像头帧 ──► [ncnn 检测骨干] ──► 每锚点: 框回归(bx) + 视觉嵌入(fx)
                                          │
文本提示词 ──► [CLIP 文本塔] ──► 文本嵌入(tx)
                                          │
              得分 = sigmoid( (fx · tx) / τ )    τ≈0.07
                                          │
                                   argmax → 类别 + 框

检测骨干与框回归完全在手机端（ncnn）完成；只有“文本→嵌入”这一步需要 CLIP 文本塔——它只在提示词变化时计算一次，开销极低，可用本机 Python 服务（或云端）提供。

3. 本 Demo 已落地的内容

  • native 解码器：app/src/main/jni/yoloworld.cpp，自动识别输出布局，温度系数 τ=0.07 可调。
  • 提示词 UI：输入框填英文逗号分隔的类别（如 person, car, dog），点“应用提示词”即把文本嵌入送进 native。
  • 文本塔服务：yoloworld_text_tower.py，真实 CLIP（--clip）或确定性 mock（默认，用于打通链路）。
  • 算法自测：tools/test_decode.py 用合成张量验证打分/NMS/去 letterbox，无需模型权重。
  • 模型转换：convert_yoloworld_ncnn.py，把官方 YOLO-World 权重转成此 Demo 约定的 ncnn 模型。

4. 拿到模型后即可运行

# 1) 启动文本塔 (PC 端)
python yoloworld_text_tower.py --mock      # 演示
python yoloworld_text_tower.py --clip       # 真实 CLIP

# 2) 把模型放进 assets 并构建
cp yoloworld.param yoloworld.bin app/src/main/assets/
./gradlew assembleRelease && 用 apksigner 签名

# 3) App 内填“文本编码器地址”为 http://<PC局域网IP>:8000
#    (模拟器用 http://10.0.2.2:8000)，输入提示词，点应用。

5. 调参提示

参数（yoloworld.cpp 顶部常量）含义说明
YW_TEMPERATURE温度 τYOLO-World 默认 0.07；与文本塔对齐不好时调大
YW_PROB_THRESHOLD置信度阈值开放词汇建议 ≥0.3，背景多可上调
YW_BOX_FORMAT框格式0=(x1,y1,x2,y2) 1=(cx,cy,w,h)，按导出格式选
YW_BLOB_*输入/输出 blob 名与你的 ncnn 导出一致即可
